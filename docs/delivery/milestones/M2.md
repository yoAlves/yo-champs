# M2 — Real providers

**Status:** implementation complete; final gate, review and PR pending.
**Depends on:** M1 green + review (done).

## Goal

Make the loop real: a data-driven provider profile, an OpenAI-compatible
streaming client, Keychain storage, settings UI and JSON persistence, with clear
errors and no vendor name in Core.

## Non-goals

- No Anthropic/Gemini-specific clients, OpenCode runtime or local MLX models.
- No tools, MCP, RAG or multi-provider routing beyond profiles.
- No character work beyond placeholder states.

## Deliverables

1. `YoChampsProviders`: `OpenAICompatibleProvider`, SSE parser,
   `ProviderRegistry`, robust error mapping, retries/timeouts as configured.
2. `ProviderProfile`/`Capability` in Core; example profiles in docs only.
3. Keychain `SecretStore` (service `com.yurioliveira.yochamps`), `secretRef`
   in `config.json`.
4. JSON conversation store under `~/Library/Application Support/YoChamps/`,
   schema-versioned, with restart persistence.
5. Settings: base URL, model, key, headers, “Test connection”; onboarding when
   no profile exists.
6. Multi-turn persistence and clear-history action.
7. Integration tests against a local stub server; secret scan still green.

## Acceptance criteria

- [x] Real Q&A works against an OpenAI-compatible endpoint (`make provider-check`
      runs the real client against a local SSE stub).
- [x] Key lives only in Keychain; config/logs/fixtures contain no secret
      (`secretRef` only; encoder rejects credential headers; gitleaks clean).
- [x] Restart keeps history; switching profile keeps conversations valid
      (`FileConversationStore` restart test; history is profile-independent).
- [x] Missing key, invalid model, timeout, rate limit and cancellation show
      distinct, actionable errors (typed `LLMError` + Settings display).
- [x] `grep` for provider/vendor names in `Sources/YoChampsCore` returns nothing.
- [x] `make verify` and `make provider-check` green.

## Verification commands

```sh
make test
make verify
make provider-check
```

Manual evidence: configure a personal profile, ask, restart, confirm history.

## Risks

- SSE edge cases (multiline data, `[DONE]`, partial UTF-8); test fixtures.
- Keychain prompts in tests; inject a fake `SecretStore`.
- Schema drift on disk; write `schemaVersion` and a migrator from day one.

## Exit criteria

Integration and secret-scan gates green, evidence in `status.md`, review with
no open critical/important findings.
