# v0.1.2 — Provider reasoning effort

**Released:** 2026-11-19 · **Tag:** `v0.1.2` (after merge) · [Changelog](../../../CHANGELOG.md)

A small additive release: provider profiles can carry a reasoning effort, so a
model variant can be selected without changing the model id or adding a catalog.

## Highlights

- **Settings:** enter `model#effort` in the Model field (for example
  `deepseek-v4.1-flash#low`). The suffix is input syntax only: `config.json`
  keeps the bare model id and a separate `reasoningEffort` string.
- **Wire:** the request body carries top-level `reasoning_effort` only when the
  profile configures one; without it the key is absent. The value is a free
  string and the provider validates it.
- **Composition:** the Ask engine builds its agent from the selected profile,
  so the effort reaches real requests, not just Test Connection.

## Upgrade

Nothing to migrate: `config.json` stays at `schemaVersion` 1. Old files load
without the key, older apps ignore it, and Settings re-displays an existing
effort as `model#effort`.

## Known limitations

- `#` is reserved as the model/effort separator; a literal model id containing
  `#` is not supported.
- No allowlist of valid variants: an unknown one fails at the provider.
- A provider that needs a different wire shape (for example `reasoning: {effort}`)
  needs a future additive profile change.
