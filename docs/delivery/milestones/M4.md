# M4 — Hardening and V0 release

**Status:** not started (blocked by M3 gate).
**Depends on:** M3 green + review.

## Goal

Make V0 trustworthy and shippable locally: evals, injection resistance,
timeouts/retries, performance checks, complete docs, release workflow and tag
`v0.1.0`.

## Non-goals

- No App Store, notarization, auto-update or Sparkle in V0.
- No new product surface: V0.1 features stay out.
- No MCP, OCR, transcription, calendar, RAG or local models.

## Deliverables

1. `YoChampsEvals`: 5–10 fixtures (short answer, refusal, injection, error
   recovery), runner and report artifact.
2. Prompt-injection guardrails: hierarchy, data fencing, adversarial fixture.
3. Timeouts, retry/backoff policy, cancellation hardening.
4. Performance report: cold start, idle memory, bundle size, first token.
5. Release workflow: `make release-dry-run`, version/tag steps, changelog.
6. Final docs pass: README, SECURITY, ASSETS, architecture, ADRs, status.
7. Recorded demo (sanitized) and public checklist.

## Acceptance criteria

- [ ] Eval suite runs and reports pass/fail per fixture.
- [ ] Injection fixture cannot override the system contract.
- [ ] Timeouts and retries behave as documented; no hanging requests.
- [ ] Metrics reported against targets (no early blocking).
- [ ] `make release-dry-run` produces a local app/DMG without signing.
- [ ] `make verify` green; tag `v0.1.0` created.
- [ ] Public checklist complete: licenses, disclaimer, README, CI, security.

## Verification commands

```sh
make verify
make eval
make release-dry-run
make secrets
```

Manual evidence: recorded demo of the full V0 loop, checklist review.

## Risks

- Evals with a weak model are noisy; keep them small and deterministic where
  possible.
- Release work drifting into signing/notarization; that is post-V0.
- Scope creep from V0.1 wishes; file them in the roadmap, do not implement.

## Exit criteria

All M4 criteria checked, tag `v0.1.0` created, evidence in `status.md`, review
with no open critical/important findings, and the V0 definition of done in
`docs/product/v0.md` satisfied.
