# v0.1.0 — Functional V0

**Release date:** 2026-11-17 · **Tag:** `v0.1.0` (pushed after the release PR
merges) · [Repository](https://github.com/yoAlves/yo-champs)

First functional release. Yo Champs is a native macOS menu bar companion with an
original paperclip character (Champ) and a provider-agnostic LLM loop. Ask from
the menu bar or the global hotkey, get a short streamed answer, keep multi-turn
context, and switch provider/model in Settings.

## What is in this release

- Menu bar app (`LSUIElement`, no Dock icon) with Ask, Show/Hide Ask, Settings
  and Quit.
- Global hotkey ⌥⌘K by default, customizable; Esc hides Ask without quitting.
- One Ask window: chat transcript, input row, embedded animated Champ, resizable
  frame persisted across launches.
- OpenAI-compatible streaming provider with provider profiles, SSE parsing,
  typed errors and retries; API keys in the macOS Keychain.
- Settings/onboarding with base URL, model, headers and “Test connection”.
- Multi-turn history persisted as versioned JSON and reused as context; the
  visible transcript starts fresh on relaunch. New chat via `+` or ⌘N.
- Mascot packs: the original Champ pack and local packs, validated by
  `make mascot-validate`.
- XCUITest critical flow: hotkey, Esc, show/hide, embedded mascot layout, new
  chat.

## Install locally

```sh
git clone https://github.com/yoAlves/yo-champs.git
cd yo-champs
make bootstrap
make doctor
make verify
make deploy
```

`make deploy` is local-only: unsigned, not notarized, not published. There are
no downloadable binaries in this release; build from source.

## Not included yet

- M4 hardening is a post-release backlog: evals, injection fixtures, performance
  report, `make release-dry-run`, recorded demo and the public checklist.
- V0.1 features: slash commands, model picker, copy/retry, markdown streaming.
- Out of V0 scope: OCR, transcription, calendar, web search, MCP, RAG, local
  models, auto-update, telemetry, App Store and signed distribution.

## Known limitations

- Local builds are ad-hoc signed and unsigned for distribution; macOS may ask
  for Keychain access on first run.
- A real answer needs a personal provider profile and key; UI tests run with
  `--demo` and the `MockProvider`.
- The visible transcript starts fresh on relaunch; prior turns are loaded as
  model context only (`history.json`).
- `make test-ui` needs full Xcode and the suite is order-sensitive: stop any
  installed instance (`make stop`) before running it.
- macOS 14+ on Apple Silicon first.
