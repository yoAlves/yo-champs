# M1 — Conversation loop

**Status:** not started (blocked by M0 gate).
**Depends on:** M0 green + review.

## Goal

Prove the core loop end to end with a fake provider: ask a question, stream a
1–2 sentence answer into a floating bubble, cancel it, and keep turns in memory.

## Non-goals

- No real network provider, Keychain, settings UI or persistence (M2).
- No character renderer, drag or asset animation (M3).
- No tools, MCP, RAG or slash commands.

## Deliverables

1. Core contracts: `LLMProvider`, `LLMRequest`/`LLMMessage`/`LLMEvent`, `Clock`,
   `ContextBuilder`, `ConversationStore` (in-memory), `CompanionEngine`.
2. `YoChampsProviders` target with `MockProvider` and a contract test suite.
3. App: prompt panel (hotkey wiring can be minimal), streaming bubble,
   cancellation, Esc to close.
4. Semantic `CompanionState` transitions: idle → thinking → streaming → idle/happy/error.
5. Error surface for cancellation and provider failures.
6. `make test` covers engine, context budget and contract; `make demo` runs a
   fixture conversation.

## Acceptance criteria

- [ ] Asking the mock provider yields 1–2 sentences streamed token by token.
- [ ] Cancel stops the stream within a beat and returns to idle.
- [ ] Multi-turn context includes the last turns under a token budget.
- [ ] New chat clears context without restarting the app.
- [ ] Zero provider/vendor names inside `YoChampsCore`.
- [ ] `make verify` green.

## Verification commands

```sh
make test
make verify
make demo
```

Manual evidence: question → streamed answer in the bubble; cancel mid-stream.

## Risks

- Streaming cancellation leaking tasks; assert task termination in tests.
- SwiftUI state updates off the main actor; keep DTOs `Sendable` and hop once.
- Bubble placement without a character window yet; use a temporary anchor.

## Exit criteria

Contract tests and demo pass, `make verify` green, evidence in `status.md`,
review with no open critical/important findings.
